## What the complete discussions establish

**#1665 — queue semantics need game and tick boundaries.** The opening report suspects existing movement actions delay Tethoril's dialogue payload, and considers clearing or prepending actions. Comments add IWD2 Izbelah, then reject the initial ActionOverride interruption test as unsuitable. A revised non-pausing-dialogue test initially appears to preserve the queue. The [last technical comment](https://github.com/gemrb/gemrb/issues/1665#issuecomment-2515475293) corrects that inference using Bubb's reported original-engine observations: EE 2.5.16.6 clears the NPC's queued actions at the beginning of the next logic tick, preserves the currently executing action, and appends selected response actions with a corresponding tick delay. It reports original BG2 also clearing on dialogue-file switches and IWD2 omitting those clears. These are attributed upstream research observations, not measurements independently repeated in LAB. The remaining movement in the revised test therefore does not prove that no clearing occurred.

For Redux, callback dispatch, queue entry, action execution and completion must remain separate evidence boundaries. A future queue-parity journey needs already-running distinguishable work, tick-relative observations, both pausing/non-pausing dialogues and the appropriate game variant. Our current stock Jaheira path does not cover that matrix. The pinned local `DialogHandler.cpp:230–256` already treats IWD2 differently through `RULES_3ED` and checks interruption flags before `Stop`; its transition path processes/appends actions and conditionally adds `BreakInstants`. This partial structural correspondence does not demonstrate the upstream one-tick contract.

**#2345 — fades can alter semantic sequencing.** The report traces a PST fade/wait/fade/class-change sequence, questioning whether blocking all time during fades causes extra phases and premature fallback clearing. Stopping script processing while allowing execution, engine-specific behavior and dialogue-versus-script differences are proposed investigations, not resolved conclusions. Its only comment supplies no technical confirmation. Our Window buffer correction concerns redraw/composition of dirty regions; it neither changes `GlobalTimer` fade progression nor validates this class-change payload sequence. Any future test must capture fade phase, timer/script progress and payload outcome, rather than infer success from one faded screenshot.

**#2206 — feedback may hide a scripting defect, but the causes are not established.** The initial report describes instant battle-square victories and suggests replacing an override script. It separately suspects rapid `FloatMessage` calls overwrite progress feedback, while allowing that feedback could be a distinct issue. The [sole comment](https://github.com/gemrb/gemrb/issues/2206#issuecomment-2644132254) records that removing `override/iwd2/41parena.bcs` prevents selecting squares, so deletion is not a validated solution. Preserve that override and this distinction between state outcome and visible message ordering. No evidence connects this IWD2 case to stale response pixels, and neither of our dialogue fixes establishes ordered floating-message behavior.

**#259 — wrong branch is distinct from stale branch pixels.** The reporter describes a scripted Valygar quest conversation selecting player-initiated dialogue instead, repeatedly restarting and blocking progress; removing the PID block helps, while moving it does not. The reporter says an EE playthrough supported the mod working there. A historical `IsGabber` experiment checking target rather than speaker is reported to advance matters, but no complete production fix is established. The ten comments discuss required mod components, quest prerequisites and the maintainer's forced-join setup; the maintainer never obtains a reliable reproduction. The reporter also describes a subsequent NPC-to-NPC initiation failure after bypassing PID. Those are unresolved reproduction boundaries, not proof of one shared cause.

The [first comment](https://github.com/gemrb/gemrb/issues/259#issuecomment-541860020) explicitly says historical commit [0884151](https://github.com/gemrb/gemrb/commit/0884151919481eb0ad67ed79107f9ea67187429b) did not fix this report. Inspection confirms that commit protected a final dialogue action payload with cutscene-mode actions and claimed a different issue, #256. Do not adopt that old patch or a speaker/target substitution as a verified #259 solution. The current pinned `Triggers.cpp:362–371` still implements `IsGabber` through `IsSpeaker`; source resemblance alone establishes neither reproduction nor correctness for this mod.
