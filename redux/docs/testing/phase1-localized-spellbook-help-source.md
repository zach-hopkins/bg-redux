# Localized spell-memorization help: source investigation

There is no exact TLK strref for the shipped `SPELL_MEMORIZATION_HELP` literal in the measured English installation. The safest option using existing GUI APIs is the **full localized TLK 39254 paragraph**, explicitly accepted as a longer related instruction rather than an exact copy of the original named literal. If exact named-string fidelity is required, a small nonexecuting resource/string lookup is needed; a Lua interpreter is unnecessary. No engine or helper changes are made by this note.

## Existing localized API option

`GemRB.GetString(39254)` or a suitable control's `SetText(39254)` uses the configured TLK through the existing engine string manager. GUIScript.cpp lines 440–476 and 1314–1344 implement these APIs; `Control_SetText` accepts either a numeric strref or a Python Unicode string and resolves TLK tokens for strrefs. A wrapping TextArea can be created through the existing GUIClasses.py `CreateTextArea` entry (line 183). Rendering fit, scrolling, fonts, markup/tokens and live locale behavior still need bounded verification.

English 39254 is 265 characters: its first 177 characters exactly equal the original help, followed by an extra sentence directing the user to the book/scroll icons. The complete extra English sentence is: “Select the Mage Book or Priest Scroll icon that appears on the left edge of the screen.” English 39295 currently duplicates it. All 12 installed TLKs have nonempty 39254, with translated lengths 96–384 characters. Only English and Polish are exact literal prefixes; the other translations differ. Therefore **show the whole localized paragraph** if this option is chosen. Do not take the first 177 characters, split the first sentence, remove an English suffix, or claim that 39254 reproduces every locale's named Lua string. A strref existing in this data set is not a guarantee for every game version/mod; gate the UI to the intended BG2EE data and handle missing/empty data explicitly.

Other English candidates exist but differ: 39255/39296 describe selecting spells and resting; 16215 contains older right-click navigation instructions; 99845 and related entries describe touch navigation. They are not exact replacements and should not be silently substituted based on similarity. No hardcoded English fallback is needed or recommended.

## Exact literal route without Lua execution

C++ already has `ResourceManager::GetResourceStream` (ResourceManager.h:45), inherited by GameData (GameData.h:123), and `IE_LUA_CLASS_ID` is 0x409 (SClassID.h:42). `GameScript::INI` at Triggers.cpp:4769 already reads Lua resources as text without interpreting them. That narrow substring probe is not a safe general string-table parser and should not be copied as one.

The current GUIScript method surface has typed loaders (`LoadTable`, `GetSpell`, etc.) and `HasResource`, but no observed raw-resource or named `uiStrings` getter. `GetGameString` is a fixed small set of game metadata, not a localization-key API. `GetSystemVariable` exposes paths/screen options but does not expose `GameLanguagePath`. The language is configured in InterfaceConfig.h:45, used for the active dialog.tlk in Interface.cpp:507 and language-data BIF injection at Interface.cpp:388. Do not derive the language from Windows locale, assume English, or bypass resource precedence with an ad hoc filesystem path.

A future minimal API could select `L_<configured locale>` through the existing resource manager and return only the requested plain string after a strict bounded data parse. It must not execute Lua, `eval`, import resources as code, or emulate arbitrary expressions. Required rules include resource/decoded-length bounds; a real tokenizer that skips comments and recognizes quoted/long strings; exact key/table matching; duplicate-key rejection; strict UTF-8 and supported Lua escape semantics; no concatenation, function calls or dynamic expressions; and explicit failure for unsupported syntax. Do not use Python `unicode_escape` on UTF-8 translations or a line regex as the production parser. Multibyte text, escaped quotes/backslashes/newlines, numeric escapes, long brackets, comments, duplicate keys and malicious expression inputs need meaningful negatives. The private survey used a bounded known-assignment reader only to characterize these local assets; it is not a production parser.

If the requested locale/resource/key is absent or unsupported, return a missing result and omit the optional help panel, or deliberately use a separately specified localized TLK paragraph such as 39254. That policy must be explicit; never silently fall back to English or claim exact translation equivalence. Override and language-resource precedence, runtime locale switching/cache invalidation, display markup and unsupported mod resource syntax remain design decisions for implementation, not solved by this source survey.

Recommendation: use the existing TLK 39254 full paragraph if the longer localized instruction fits the intended help pane and its wording is accepted. If exact original `SPELL_MEMORIZATION_HELP` is required, schedule the bounded resource lookup separately. Neither approach justifies a Lua interpreter or publication of copyrighted language assets.

## Source fit for the proposed name-selection UI

The full 39254 paragraph describes choosing prepared spells and then resting, rather than prescribing a particular known-row gesture. Its extra sentence describes entering the book through the left-edge icon. That instruction matches the existing measured native OPTWIN wizard/priest entries and remains appropriate if the intended page supports both an icon shortcut and known-name selection followed by a separate Memorize button. Original ui.menu supports that combination: mage known-list `cellNumber == 1` memorizes through the icon cell (around lines 8020–8028); the name column uses `currentBookSpell`; the separate Memorize button invokes the selected original index (8222–8232). Priest list icon-cell logic is at 8755–8762 with its corresponding separate button below the list. Therefore the localized full paragraph is a practical existing-API source for that design; no exact-key parsing seam is needed just to provide useful localized help. This is a source-context assessment, not execution or layout-fit validation.

## Confirmation-policy context discovered in the same caller source

The complete original prepared-list callers contain an option-dependent prompt, which the previously extracted direct unmemorize function bodies alone did not show. Mage ui.menu:8185 and priest:8825 call the confirmation popup when `findMemorizedUncastable(resref) == -1` and `Infinity_GetOption(41, 9) ~= 0`; otherwise they call the direct function. The feedback toggle table at 3381 maps option 41 to ENABLE_CONFIRMATION_LABEL/HELP, and OPTIONS_FEEDBACK sets panel 9 around 3432. English L_en_US.lua:277–278 identifies this as **More Confirmation Prompts**, explaining that it prompts before removing memorized spells or resting at inns.

The original measured no-prompt operation remains valid for its observed configuration; the unconditional BG2EE direct policy and its successful AFTER receipts establish that bounded case, not every original option state. Neither the original option-on popup behavior nor the same-resref depleted-entry preference has been measured in the current native journey. This is a separately identified compatibility gap, not a reinterpretation of earlier raw PASS/failure receipts. Do not describe all BG2EE prepared removal as universally prompt-free. No production change is proposed or made here.
