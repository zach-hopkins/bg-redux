# Spellbook actor and content coverage correction

The recruited-menu run `20261022T054632Z-guarded-recruited-menu-run-a098a21f` exposed an external harness defect: its priest applicability row selected actor 3 (40 known spells, 11 slots), but the 1024×768 capture 25 displayed the protagonist `wfsdf`, an empty spellbook, and native single selection 1. This observation rejects eligible-caster content coverage from that capture, irrespective of its transition checks. Earlier mage window-presence checks likewise did not establish which actor's spells were displayed. Historical receipts remain unchanged.

`GUICommonWindows.SetSelectionChangeHandler` resets single selection from `GameGetFirstSelectedPC` when entering a top window from walking mode (`gemrb/GUIScripts/GUICommonWindows.py:112`). The old adapter changed only `GameSelectPCSingle`; it left walking selection on the protagonist. The ordinary portrait callback selects walking party members with `SELECT_REPLACE` (`GUICommonWindows.py:309`). `GUIMG.ToggleSpellWindow` also reads single selection *before* its loader to choose a sorcerer book (`GUIMG.py:36`). These are distinct selection channels with a required ordering, rather than evidence of a production spellbook defect.

The revised external journey requests the eligible actor's actual registered PORTWIN portrait callback, rejects targeting mode or an active top-window selection handler, and checks the portrait's actor value. On the next timer boundary it verifies walking selection, aligns ordinary single selection, and requests the existing OPTWIN spellbook callback. It then requires the independently captured single selection and displayed name to identify that same actor. Native callback receipts bind both actions to their runtime step and owned run nonce; stale, missing, duplicate or wrong-target receipts fail validation.

For the actual displayed level, the runtime queries known spells and memorized slots, preserves resrefs and original indices, and sorts known spell names as the stock BG2EE scripts do. The native observer records actual control values, raw and effective tooltips, flags, dimensions and public Picture presence. The validator checks every populated and empty slot in the BG2EE 24-known/12-memorized layout against that contract, including removal of stale empty-slot tooltip/picture flags. An empty displayed level cannot pass populated-book coverage. Sorcerer books explicitly omit the memorized grid; unsupported capacity or missing controls fail closed.

The observation uses public exports: `Control::GetValue`, `View::TooltipText`, and `Button::DragCursor` (`Control.h:162`, `View.h:251`, `Button.cpp:450`). The latter returns the button Picture, but the base `Control::DragCursor` can return a debug cursor (`Control.cpp:263`). The adapter declares Picture observation unavailable when that fallback is active. It neither starts a drag nor accesses private object layout. `Button::SetPicture` sets the picture flag (`Button.cpp:598`); visible positive dimensions, effective tooltip and enabled state are separately checked.

This proves bounded slot assembly only after fresh execution. Tooltip/value/Picture presence does not independently identify sprite resource pixels, prove readiness-border appearance, test spell learning/memorization/casting, exercise OS pointer hit testing, or establish original-engine visual parity. Resrefs and readiness flags in the contract are read through game APIs; they are not native sprite provenance or visual readiness evidence. Screenshot inspection remains necessary for readability, overlap and correct icon appearance.

This source-only change adds negative cases for walking-selection failure, loader reset, targeting mode, old window-only receipts, stale/wrong callbacks, wrong actor, blank or stale tooltip, wrong slot value, missing or unobservable picture, zero geometry and missing/duplicate controls. No tests, build or native runtime were executed by this worker. The coordinator must run the focused/full suites, rebuild the external menu host against the preserved candidate, and rerun both resolutions with actual eligible mage and priest actors. No engine source or binary is changed by this correction.
